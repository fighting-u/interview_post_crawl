## 高并发与注册流程优化
2. 能不能只用一种数据库？为什么不只用 Redis，选择 MySQL 的依据是什么？
   AI 简要回答：Redis 是内存数据库，易失性高且成本高昂。MySQL 提供持久化和复杂事务能力。二者互补：Redis 做缓存/热点读写，MySQL 做冷数据和核心资产存储。

3. 注册流程中的布隆过滤器、分布式锁和唯一索引，分别解决什么问题？
   AI 简要回答：
   *   **布隆过滤器**：拦截大量不存在用户名请求，防 DB 穿透。
   *   **分布式锁**：保证写 DB 时并发安全。
   *   **唯一索引**：作为最后一道防线，防止极端并发下脏数据入库。

4. 布隆过滤器判断用户名存在时，后续怎么处理？如果误判导致用户无法注册，怎么办？
   AI 简要回答：
   *   **处理**：通常返回“用户名已占用”或直接拒绝，不再查库。
   *   **误判**：这是布隆过滤器的固有特性（False Positive）。如果是关键业务（如注册），建议布隆过滤器 + 二级缓存/重试查库（降级模式）来双重确认。

5. 布隆过滤器更新失败怎么办？如果重试一直失败，后续如何处理？
   AI 简要回答：采用异步刷新机制。若实时更新失败，可将其放入本地 Buffer，稍后批量写入或触发告警人工介入。

6. 有人疯狂请求注册接口，如何限流？具体按什么维度识别和拒绝请求？
   AI 简要回答：
   *   **算法**：令牌桶 (Token Bucket) 或漏桶 (Leaky Bucket)，配合 Redis + Lua 脚本实现。
   *   **维度**：IP 地址、手机号、设备指纹。

7. 如何使用 requestId 实现幂等？
   AI 简要回答：在 Request 头携带全局唯一 ID。在处理前检查 Redis Key(`idempotent:{requestId}`)是否存在，不存在则创建并执行业务；存在则直接返回历史结果。

8. 既然 requestId 可以防重，为什么还需要加锁和二次校验？
   AI 简要回答：防止 "Check-Then-Act" 竞态条件。即 A 和 B 线程同时发现 Redis Key 不存在，可能都会尝试执行。加锁是为了串行化关键代码段。

## 存储中间件 (Redis / MySQL / Mongo)
9. Redis 有哪些持久化方式？AOF 持久化的具体流程是什么？
   AI 简要回答：RDB (快照) 和 AOF (追加日志)。
   *   **AOF 流程**：写命令 -> 写入 OS Page Cache -> 异步刷盘 (fsync)。分为 always, everysec, no 三种策略。

10. AOF 与 RDB 应该如何选择？
    AI 简要回答：AOF 数据更安全但体积大、恢复慢；RDB 数据有间隔丢失风险但速度快。生产环境通常**两者搭配使用**。

11. 如何保证数据库与缓存的一致性？并发读写时出现旧数据怎么办？
    AI 简要回答：
    *   **延迟双删**：先删缓存 -> 更新 DB -> 休眠片刻 -> 再删缓存。
    *   **Canal 监听 Binlog**：异步消息通知删除缓存。

13. 如果 Redis 数据全部丢失，如何恢复面试进度？
    AI 简要回答：通过 RDB/AOF 文件恢复到最近一次检查点；或通过 MySQL 重建热点数据。

14. Redis Stream 的消费者处理到一半宕机，会发生什么？
    AI 简要回答：该消费组在该条目上状态变为 pending。重启后消费者会在下次心跳检测或拉取时发现该未 ACK 的消息，通常会由其他消费者重新处理（At-least-once）。

15. 如果 Redis 自身宕机，如何优化系统可用性？
    AI 简要回答：搭建 Redis Cluster 或 Sentinel 主从切换；应用层增加超时熔断保护，允许短时间读旧数据或回源 DB。

16. 会话级 FIFO 能否保证顺序？多个 Worker 同时执行时如何协调？
    AI 简要回答：单 Channel 可以保证严格 FIFO。多 Worker 竞争同一个 Channel 时会有负载均衡，但同一用户的消息会被分配给特定 Worker 才能保持上下文顺序（Hash Sharding）。

## RAG (检索增强生成) 专项
17. 请解释 RAG 从文档上传、处理到检索和回答的完整流程。
    AI 简要回答：
    1. **ETL**：PDF/Word 解析 -> Text Splitting (分块) -> Embedding (向量化)。
    2. **Index**：存入 Vector DB。
    3. **Retrieve**：用户提问 -> Embedding -> 相似搜索。
    4. **Generate**：原始问题 + Context Chunk -> LLM Prompt -> 回答。

18. 如何评估 RAG 或重排的效果？自己出的几个问题能否代表真实用户的各种提问？
    AI 简要回答：
    *   **指标**：召回率 (Recall)、精确率 (Precision)、答案忠实度 (Faithfulness)。
    *   **数据集**：必须构建涵盖各类意图、长度、专业度的测试集 (Golden Dataset)，避免 Overfitting。

## Java 基础与系统设计
20. HashMap 为什么线程不安全？线程安全的替代方案如何实现？
    AI 简要回答：**HashMap** 多线程扩容会导致死循环 (JDK 7) 或数据覆盖 (JDK 8)。替代方案：ConcurrentHashMap 或 Collections.synchronizedMap()。

21. MySQL 为什么需要两阶段提交？redo log 和 binlog 如何协调，故障后如何恢复？
   AI 简要回答：为了保证崩溃恢复后的 ACID 特性。
   *   **Phase 1**: 准备 (Prepared)，写入 Redo Log。
   *   **Phase 2**: 提交 (Commit)，写入 Binlog，更新 Redo Log 状态。
   *   **恢复**：根据 Redo Log 恢复事务到最终状态。

22. 事务有哪些特性？
    AI 简要回答：ACID (原子性 Atomicity、一致性 Consistency、隔离性 Isolation、持久性 Durability)。

23. 死锁有哪些必要条件？
    AI 简要回答：互斥、请求保持、不可剥夺、循环等待。

24. 事务有哪些隔离级别？分别是什么意思？MySQL 默认的隔离级别是什么？
   AI 简要回答：
   *   读未提交、读已提交 (消除脏读)、可重复读 (消除脏读+不可重复读)、串行化。
   *   MySQL 默认：**可重复读 (RR)**。

25. 读未提交可能出现哪些读异常？脏读、不可重复读和幻读分别是什么情况？
   AI 简要回答：
   *   **脏读**：读到别人没提交的垃圾数据。
   *   **不可重复读**：前后两次查询同一条数据，结果不一样（值被改了）。
   *   **幻读**：前后两次查询范围，行数不一样（有人插入/删除了数据）。

26. Redis 的 key 过期之后，内存会立即释放吗？
   AI 简要回答：不会。过期只是逻辑标记。物理释放依赖惰性删除 (Lazy Expiration) 访问时清理，或定期删除 + 内存淘汰策略。

27. AI 调用很慢，应该如何设计线程池？
   AI 简要回答：**IO 密集型 vs CPU 密集型**？LLM 调用本质是 IO 阻塞（网络等待），应设置较大的线程池或基于响应式的非阻塞 I/O (WebFlux/Coroutine)。考虑背压 (Backpressure) 机制。

28. 同一个类中的普通方法调用另一个带事务注解的方法，事务一定会生效吗？
   AI 简要回答：**不会**。因为 Spring AOP 代理限制，内部 self-call 绕过了代理对象，注解失效。需注入自身 Bean 或使用 AopContext。

29. 流式输出的断线补发如何实现？
   AI 简要回答：前端维持一个 EventSource/SSE 连接。断开重连时携带 Last-Event-ID。服务端维护已推送的历史片段，供客户端补齐缺失的部分。

30. 每段生成内容都写数据库，请求量增大后如何处理？如果改用 Redis，又如何应对其宕机风险？
   AI 简要回答：DB 压力大，可引入消息队列削峰。改用 Redis 需注意持久化配置，并在应用层容忍少量丢失或设置兜底机制。

31. 前端断线或者用户主动停止时，整个后台任务是否应该取消？已经调用的工具能否停止？
   AI 简要回答：
   *   **前台停止**：通知 Agent 暂停。
   *   **底层工具**：如 SQL 已发出无法中途撤回。应支持 Cancel Token 或开启新事务的回滚（如果支持）。

32. Java GC 有哪些基本算法？它们分别如何工作？
   AI 简要回答：
   *   **标记-清除**：碎片化严重。
   *   **复制算法**：内存利用率低（早期 JVM）。
   *   **标记-整理**：老年代常用。
   *   **分代收集**：新生代复制，老年代标记整理。
