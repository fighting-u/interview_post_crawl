2. volatile 保证什么？为什么无法保证 i++线程安全？
原文回答: ...
AI简要回答：volatile 保证了可见性和禁止指令重排序，但不保证原子性。i++ 分为读、改、写三个步骤，不具备原子性，因此需要配合 synchronized 或 AtomicInteger 才能保证线程安全。

3. ConcurrentHashMap 线程安全的原理是什么？JDK1.7 与 1.8 有哪些差异？
原文回答: ...
AI简要回答：1.7 采用分段锁（Segment），将数据分成一段段存储，给每一段数据配一把锁，当某个单元只会被其一一个线程修改时才能锁住该部分。1.8 摒弃了 Segment，采用 Node + CAS + synchronized 来保证并发安全，锁粒度更细，仅锁定链表或红黑树的首节点，并发效率更高。

原文回答: ...
AI简要回答：①穿透：查询不存在的数据，绕过缓存直达 DB。解决：布隆过滤器、缓存空对象；②击穿：热点 Key 过期瞬间大量请求访问 DB。解决：互斥锁、逻辑过期不设 TTL；③雪崩：大量 Key 在同一时间过期或 Redis 宕机。解决：随机加过期时间、高可用集群方案、限流降级。

6. MySQL 为什么选用 B+树？什么是聚簇索引、回表、覆盖索引？
原文回答: ...
AI简要回答：B+树相比 B 树非叶子节点不存数据，单块磁盘能容纳更多索引项，降低树高，更适合范围查询。①聚簇索引：数据记录存放在叶子节点，InnoDB 主键索引即为聚簇索引；②回表：通过辅助索引找到主键后，再去主键索引树上查完整记录的過程；③覆盖索引：查询的列恰好是索引列，不需要回表。

## 手撕
1. LeetCode 152：乘积最大子数组；
AI简要思路：动态规划。由于存在负数可能导致最大值变最小值，需同时维护当前最大值和最小值。dp[i] = max(max_ending_here * nums[i], min_ending_here * nums[i])。时间复杂度 O(N)，空间复杂度 O(1)。

2. LeetCode 200：岛屿数量；
AI简要思路：深度优先搜索 (DFS) 或广度优先搜索 (BFS)。遍历矩阵，遇到 '1' 则发起搜索将其及其上下左右相连的 '1' 全部置为 '0'，每发起一次搜索岛屿数加一。时间复杂度 O(M*N)。
